# Codex 小说审查

> 执行前先读 [Codex 适配层](../../codex-adapter.md)。默认由当前 Codex 合并多视角审查；仅在用户明确要求并行代理时拆分。

目标是找到影响阅读、连载兑现与设定可信度的问题，并给出能落到文本的修改动作。不要为了证明作品正确而审查。

## 1. 确定范围

识别审查对象、目标平台、题材、章节范围和用户只要诊断还是也要修改。未指定模式时使用 full：

- `full`：结构、人物、连续性、文风/AI 味、平台适配。
- `lean`：结构、人物动机、设定与时间线，不做逐句润色。
- `prose`：只查文字自然度、节奏、对话与确定性反模式。

没有目标平台时使用 generic web-fiction rubric，不静默猜平台。

## 2. 加载证据

优先读取用户指定文本。工程审查再按需读取：当前章纲、最近正文、角色状态、时间线、伏笔、世界规则和文风。不要为了审一章加载整本书。

使用模块内资料：

- [质量清单](references/quality-checklist.md)
- [评分 rubric](references/quality-rubric.md)
- [剧情方法](references/plot-core-methods.md)
- [角色关系](references/character-relations.md)
- [对话](references/dialogue-mastery.md)
- [去 AI 味](references/anti-ai-writing.md)
- [禁用表达](references/banned-words.md)

参考文件不可读时继续使用下方基准，不因缺文件停止。

## 3. 审查视角

### 结构

检查核心卖点、目标—阻碍—行动—代价/反馈—新期待的最小循环、情绪曲线、信息增量、高潮兑现和章末钩子。只有解释、闲聊或流程却无状态变化时，明确指出缺失的剧情功能。

### 人物

检查行为是否符合目标、性格、处境和关系阶段；对话是否有角色差异、潜台词和信息控制；亲密、敌对、信任或能力跃迁是否有足够铺垫。

### 连续性

对照角色属性、地点、道具、能力规则、时间线、已回收/未回收伏笔和最近章节事实。区分明确冲突、证据不足和可接受留白。

### 文字

检查视角漂移、解释腔、作者替人物总结、信息倾倒、动作清单、比喻与精致体感堆叠、台词说明书、预告式结尾和模板化翻转句。保留题材需要的口语、重复与情绪直给。

### 平台

- 番茄：开局、冲突频率、情绪反馈、理解成本。
- 起点：设定自洽、升级路径、长线期待、世界承载。
- 知乎/短篇：开篇钩子、信息差、反转密度、情绪兑现、付费点。

平台规则或当前投稿要求需要精确引用时重新联网核验。

## 4. 确定性检查

按需运行：

```bash
node scripts/check-degeneration.js --check --fail-on=blocking <正文文件>
node scripts/check-ai-patterns.js --check --fail-on=blocking <正文文件>
node scripts/normalize-punctuation.js --check <正文文件>
```

这些路径相对于本 `workflow.md` 所在模块目录。逐条核对上下文；advisory 不自动改，blocking 也要给出有剧情功能的替代方式。

## 5. 严重度

- S1：设定硬冲突、关键因果断裂、人物核心动机失真、高潮兑现失败。
- S2：明显影响追读的结构、关系、节奏或信息问题。
- S3：局部文字、格式、重复、弱钩子或可读性问题。
- S4：偏好型建议；不改也不破坏作品。

不要把同一根因拆成大量重复 findings。每条问题都要有位置/证据、为什么影响阅读、最小修改动作。

## 6. 并行审查

只有用户明确要求多代理或并行审查时，拆成结构、人物、连续性、文字四个边界清楚的任务；给每个任务相同的文本范围和最小必要设定。任一代理失败时，由当前 Codex补齐对应视角，不丢弃已获得的有效证据。

## 7. 输出

先给总判断与最高优先级问题，再列 findings，最后给修改顺序。推荐格式：

```md
审查范围：
模式：full | lean | prose
目标平台：

## 总判断
## Findings
### S1
### S2
### S3
### S4
## 建议修改顺序
## 已通过的关键项
```

“已通过”只列确实核对过的关键项，不写空泛表扬。用户只要审查时停在报告；用户要求修改时，从 S1/S2 开始落实并保留原剧情意图。
