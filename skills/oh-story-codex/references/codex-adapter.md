# Codex 适配层

本文件覆盖各上游工作流中的平台专属指令。把上游方法论保留为内容，把旧平台语法转换为当前 Codex 能力。

## 语义映射

| 上游写法 | Codex 执行方式 |
|---|---|
| `/story-*`、`$story-*`、`Skill("...")` | 视为内部路由，直接读取本 skill 对应 `workflow.md`，不要要求用户再次输入命令 |
| `AskUserQuestion` | 信息确实会改变路线时使用可用的结构化用户输入；否则作合理假设继续 |
| `Read`、`Glob`、`Grep` | 使用当前文件工具；文本与文件检索优先 `rg` / `rg --files` |
| `Write`、`Edit` | 遵守当前文件权限与持久化规则；先检查目标，保留无关改动，合并而非整文件覆盖 |
| `Agent(...)`、`Task(...)`、`subagent_type`、`agent_type` | 默认由当前 Codex 直接执行；只有用户明确要求多代理/并行/委派时才使用 collaboration 工具 |
| `.claude/`、`.opencode/`、`.zcode/`、项目 custom-agent 探测 | 忽略；不要因此阻断、降级或要求部署 |
| Claude hooks、Codex CLI hooks、`story-setup` 部署 | 不在个人 skill 中安装；在交付前直接运行对应检查，项目结构按 `codex-workspace.md` 维护 |
| browser-cdp、登录态抓取脚本 | 先用网页搜索；仅在公开网页搜索成功但缺少必要交互时使用允许的浏览器能力，不操控已登录会话 |
| GPT-Image API、`GPT_IMAGE_API_KEY`、curl 出图 | 使用当前环境的 imagegen skill/tool |
| “新开/重启会话” | 不要求；继续当前任务。界面缓存只影响新安装 skill 的可见性，不影响当前适配工作 |

## 模块加载

1. 先读取模块 `workflow.md` 的目录和当前阶段。
2. 只打开它在当前步骤明确点名的参考文件；长参考先用标题或关键词定位。
3. 模块若要求调用不存在的脚本或平台命令，保留其目的，用当前工具完成同一检查。
4. 模块若要求多个 agent，把角色视角合并为一次结构化检查；用户明确要求并行时再拆分。

## 用户交互

- 不重复询问用户已经确认的设定。
- 一次只收集会阻塞下一步的关键选择，优先给 2–3 个互斥选项。
- 用户说“你来定”“不要剧透”“继续”时，直接推进并把决定体现在内容中，不先解释方案。
- 用户只要诊断或审稿时，不擅自改写全文；用户要求修改、续写或定稿时才落笔。

## 检索与引用

- 扫榜、平台规则、流行趋势、投稿要求和外部事实都属于时效信息，必须重新联网核验。
- 技术或平台数据优先使用官方页面；市场判断至少使用多个独立样本。
- 把事实、样本观察和推断分开写；无法获取登录后榜单时明确样本边界，不伪造排名。

## 正文验证

- 先人工检查剧情功能、人物动机、视角、时间线、伏笔与信息差。
- 再按需运行模块脚本。脚本命中只是候选问题；逐条结合语境处理。
- 不为了通过 lint 牺牲人物口吻、题材惯例或必要重复。
- 不输出模型内部评分、自检清单、题材提示卡名或工作流术语到小说正文。
